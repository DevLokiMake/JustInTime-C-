# JustInTime (Windows)

Приложение для планирования действий на Windows. Основной сценарий — отправить текстовое сообщение через WhatsApp Desktop в заданное время. Открытие ссылок, запуск программ, Bluetooth и Wi-Fi — дополнительные действия для проверки возможностей приложения.

Стек: C#, .NET 10, WPF, MVVM (CommunityToolkit.Mvvm), PostgreSQL, EF Core + Npgsql, Serilog.

## Структура

```
src/
  JustInTime.Core            модели, интерфейсы, DashboardService (ни от кого не зависит)
  JustInTime.Infrastructure  EF Core, DbContext, репозитории, подключение к PostgreSQL
  JustInTime.App             WPF: окна, ViewModels, навигация, DI, Serilog
  JustInTime.Scheduler       регистрация запусков в Планировщике заданий Windows (schtasks.exe)
  JustInTime.Automation      каркас (этап 6)
  JustInTime.Messaging       отправка через WhatsApp Desktop и основа для других мессенджеров
  JustInTime.SystemControl   исполнители: ссылка, программа, Bluetooth, Wi-Fi
```

## Первый запуск

Нужно: .NET SDK 10, запущенный PostgreSQL на localhost:5432.
Все команды выполняются в PowerShell из папки с `JustInTime.sln`.

1. Инструмент миграций (один раз):

```powershell
dotnet tool install --global dotnet-ef
```

2. Пароль PostgreSQL кладём в user-secrets. В Git он не попадает. Подставь свой пароль:

```powershell
dotnet user-secrets set "Database:Password" "ТВОЙ_ПАРОЛЬ" --project src/JustInTime.App
```

Хост, порт, имя базы и пользователь лежат в `src/JustInTime.App/appsettings.json`
(по умолчанию `localhost`, `5432`, `justintime_dev`, `postgres`).

3. Первая миграция и создание базы:

```powershell
dotnet ef migrations add InitialCreate --project src/JustInTime.Infrastructure --startup-project src/JustInTime.App --output-dir Database/Migrations
dotnet ef database update --project src/JustInTime.Infrastructure --startup-project src/JustInTime.App
```

База `justintime_dev` создастся сама, если её нет. Таблицы: `Tasks`, `ExecutionHistory`.
Посмотреть их можно в pgAdmin 4: Databases / justintime_dev / Schemas / public / Tables.

4. Запуск:

```powershell
dotnet run --project src/JustInTime.App
```

или открой `JustInTime.sln` в Visual Studio и запусти проект JustInTime.App (F5).

## Что добавлено на этапе 4

Как это работает:

1. При создании задачи она сохраняется в PostgreSQL и для неё создаётся одноразовое задание
   `\JustInTime\Task-{id}` в Планировщике заданий Windows. В нужное время Планировщик запускает
   `JustInTime.exe --run-due`: приложение без окна выполняет наступившие задачи, пишет результат в БД
   и закрывается. Окно приложения для этого открывать не нужно.
2. Пока окно открыто, раз в 30 секунд работает ещё и внутренний цикл. Это запасной путь (например,
   если задание не удалось создать). Оба пути безопасно работают одновременно: каждую задачу
   атомарно «берёт» только один процесс, повторного выполнения не будет.
3. При каждом запуске окна запуски в Планировщике сверяются с БД: недостающие создаются,
   лишние (от выполненных и отменённых задач) удаляются.

Правила, которые соблюдает планировщик:

- Опоздавшая задача (компьютер был выключен) выполняется, если опоздание не больше 30 минут.
  Иначе она помечается как «Ошибка» с пояснением «Пропущена», в историю пишется результат Skipped.
  Лимит меняется настройкой `Scheduler.MissedGraceMinutes` (от 1 минуты до 24 часов).
- Если результат действия неизвестен (таймаут 60 с, непредвиденная ошибка, приложение закрыли посреди
  действия), задача получает статус «Требуется действие» и сама больше не запускается: так не будет
  дублей. Повторить её можно вручную в My Tasks с подтверждением.
- Задача, зависшая в статусе «Выполняется» дольше 10 минут, переводится в «Требуется действие».
- Задачи в статусах «Ждёт разблокировки» и «Ждёт интернет» повторяются не чаще раза в минуту.
  Исполнители, которые умеют так отвечать, появятся вместе с автоматизацией интерфейса (этапы 6-9).
- Настройка `Automation.Enabled = false` останавливает выполнение любых задач.
- Если Планировщик Windows недоступен, задача всё равно сохраняется. Приложение показывает
  предупреждение, и задача выполнится, пока приложение запущено.

Какие действия выполняются по-настоящему:

- Открыть ссылку (`http`/`https`): открывается в браузере по умолчанию.
- Запустить программу: запускается через оболочку Windows. Успехом считается то, что Windows запустила
  процесс. Что программа делает дальше, приложению неизвестно.
- Bluetooth и Wi-Fi: включить или выключить (см. раздел ниже).
- Отправка сообщений пока не работает: такая задача получит статус «Ошибка» с текстом «пока не поддерживается» (этапы 8-9).

Ограничения Windows:

- Задание запускается от имени вошедшего пользователя и только пока он вошёл в систему
  (интерактивная сессия, нужна для будущей работы с окнами). Пароль не хранится.
- Если на момент запуска компьютер спал или был выключен, Планировщик выполнит запуск при первой
  возможности (`StartWhenAvailable`), а приложение само решит, не слишком ли поздно.
- Приложение берёт путь к себе из `Environment.ProcessPath`. Если переместить папку с программой,
  запуски обновятся при следующем открытии окна.

Как проверить вручную:

1. Запусти приложение, создай задачу «Открыть ссылку» через 2 минуты, например `https://example.com`.
2. Открой `taskschd.msc`: в «Библиотеке планировщика заданий» появится папка `JustInTime` с заданием.
3. Закрой окно приложения полностью.
4. Через 2 минуты браузер откроет ссылку. Открой приложение: задача в статусе «Выполнена».
5. Для проверки пропуска: создай задачу, закрой приложение, выключи задание в `taskschd.msc`, подожди
   больше 30 минут и открой приложение. Задача станет «Ошибка: Пропущена». (Или поставь
   `Scheduler.MissedGraceMinutes` = 1 в таблице `Settings`.)

Тесты: движок на реальном PostgreSQL (успех, пропуск, таймаут, отмена, дубли, зависшие задачи,
ожидание условий), запросы репозитория, XML задания, регистратор с поддельным `schtasks`, отказы исполнителей.
Миграции на этом этапе не нужны: схема БД не менялась.

Повторяющиеся задачи (ежедневно, еженедельно, ежемесячно) нужны отдельной миграции и будут следующим шагом.

## Bluetooth и Wi-Fi

Работают через `Windows.Devices.Radios` (официальный API Windows 10 и 11), без администратора и без обходов.
Порядок: найти адаптеры, запросить доступ, изменить состояние, через опрос до 10 секунд убедиться,
что состояние действительно изменилось. Успех записывается только после этой проверки.

Честные ограничения:

- Если адаптера нет, доступ запрещён Windows (Параметры, Конфиденциальность и безопасность, Радиомодули)
  или адаптер отключён аппаратным переключателем, авиарежимом или политикой, задача получает «Ошибка»
  с причиной. Включить адаптер, отключённый системой, программно нельзя.
- Авиарежим и мобильный интернет у Windows не имеют официального API для обычных приложений.
  В форме создания задачи их нет, а старые задачи с ними завершатся ошибкой.
- Документация Microsoft описывает этот API для UWP. Для классических приложений (как это) он широко
  используется, но Microsoft это отдельно не гарантирует, поэтому проверка на твоём компьютере обязательна.
- Если выключить Wi-Fi, интернет пропадёт для всех программ. Выключение Bluetooth отключит мышь и наушники.

Как проверить вручную:

1. Включи Bluetooth в Параметрах Windows. Создай задачу «Системная настройка», Bluetooth, выключить, через 2 минуты.
2. Закрой окно приложения, подожди. Bluetooth в Параметрах Windows должен выключиться, задача стать «Выполнена».
3. Повтори с включением. Потом то же для Wi-Fi.
4. Если задача получила «Ошибка», текст причины виден в My Tasks.

Проект SystemControl, приложение и тесты теперь собираются под `net10.0-windows10.0.19041.0`: так .NET подключает Windows API.

## Что добавлено на этапе 5

  Фильтры «Все», «Проблемы» (ошибка, неизвестный итог, пропуск), «Успешные». Показываются последние 200 записей.
- **Dashboard**: блок «Ошибки» теперь показывает все проблемные попытки, а не только «Ошибка».
- **Уведомления Windows** о проблемах: ошибка, пропуск (компьютер был выключен), неизвестный результат,
  задачи, прерванные закрытием приложения. Приходят и тогда, когда задачу выполнил фоновый запуск без окна.
  Успешные задачи по умолчанию молчат (включается в Settings).
  Если за один прогон событий больше 3, показывается одно сводное уведомление.
  Ожидание разблокировки или интернета уведомлением не считается: такая задача повторяется каждую минуту.
  Сбой уведомления только пишется в журнал и не мешает выполнению задач.
- **Settings**: автоматизация вкл/выкл (выключатель, который раньше был только в БД), допустимое опоздание
  (1-1440 минут), уведомления вкл/выкл, уведомления об успехе.
- Зависимость: `Microsoft.Toolkit.Uwp.Notifications` 7.1.3 (стабильный пакет Microsoft для уведомлений
  классических приложений, сам регистрирует приложение в Windows).

Как проверить вручную:

1. Создай задачу «Запустить программу» с несуществующим путём, например `C:\no\such.exe`, через 2 минуты. Закрой окно.
2. Через 2 минуты придёт уведомление Windows «Ошибка: …, Файл не найден».
3. Открой приложение: History покажет попытку со статусом «Ошибка», Dashboard покажет её в блоке «Ошибки».
4. В Settings включи «Уведомлять и об успешных задачах», создай задачу «Открыть ссылку» и дождись уведомления.
5. В Settings выключи автоматизацию, создай задачу через 1 минуту: она не выполнится. Включи обратно и сохрани.

Если уведомление не пришло, проверь: Параметры Windows, Система, Уведомления, включены ли уведомления и не включён ли режим «Не беспокоить» (Фокусировка). Причину сбоя смотри в логе `%LocalAppData%\JustInTime\logs`.

Тесты: решение об уведомлениях (что показывать, сводка, тихий успех, выключатели), сохранение и проверка настроек,
запрос журнала по результатам на PostgreSQL. Экраны и сами всплывающие окна проверяются вручную.
Миграции на этом этапе не нужны: схема БД не менялась.

## Что добавлено на этапе 6

Основа для автоматизации окон программ. Отправки сообщений здесь ещё нет: сначала нужно увидеть, что реально
доступно в окнах WhatsApp и Telegram (этапы 8-9 пишутся по этим данным).

- **Модуль Automation** (Windows UI Automation, `System.Windows.Automation`):
  - поиск окон верхнего уровня по имени процесса или заголовку (окно самого JustInTime игнорируется);
  - поиск элементов по имени, AutomationId, типу и классу. Координаты экрана не используются;
  - неоднозначный поиск (подходит больше одного элемента) возвращает `Ambiguous`: автоматизация обязана остановиться;
  - ожидание появления элемента с тайм-аутом и отменой;
  - действия через официальные шаблоны: Invoke (нажать), Value (ввести и прочитать текст); нет шаблона или элемент
    исчез, значит понятная `UiAutomationException`, а не молчаливый сбой;
  - снимок дерева элементов в текстовый файл. Значения полей ввода не читаются, имена обрезаются до 60 символов.
- **Ожидание разблокировки**: исполнитель с `RequiresInteractiveDesktop` не запускается на заблокированном
  компьютере. Задача получает статус WaitingForUnlock, попытка и запись в историю не создаются, проверка повторяется
  раз в минуту, после разблокировки задача выполняется. Если ждала дольше допустимого опоздания (Settings), она
  помечается пропущенной. Об ожидании приложение сообщает один раз, без спама.
  Состояние стола определяется через `OpenInputDesktop`: на экране блокировки, при защищённом окне UAC и в
  отключённом сеансе стол не «Default». Отдельного официального флага «заблокировано» у Windows нет, поэтому при любом
  сомнении стол считается недоступным: лучше подождать, чем вводить текст вслепую.
- **Экран Automation**: состояние рабочего стола и кнопка «Сделать снимок» для WhatsApp, Telegram или любой части названия.
- **Ключ `--dump-ui`**: `JustInTime.exe --dump-ui WhatsApp` сохраняет снимок и закрывается (база данных не нужна).

Снимки лежат в `%LocalAppData%\JustInTime\ui-dumps`.

Как проверить вручную:

1. Открой WhatsApp и Telegram (окна не сворачивай в трей), в приложении зайди в Automation, нажми «Сделать снимок» для каждого.
2. Открой файлы из папки со снимками. Там должны быть строки вида `[Button] name="..." patterns=Invoke`.
   Если дерево почти пустое, это тоже результат: значит у окна ограниченная доступность и адаптер придётся делать иначе.
3. Заблокируй компьютер (Win+L), создай заранее задачу «Запустить программу» через 1 минуту: она выполнится (ей интерфейс не нужен).
   Задачи, которые управляют окнами, появятся на этапе 8 и будут ждать разблокировки.

Тесты: поиск (в том числе неоднозначный, глубина, лимиты, исчезнувшая ветка, ожидание и тайм-аут, отмена), снимок,
сохранение файлов, ожидание разблокировки в движке и в репозитории (PostgreSQL).
Сам UI Automation и `OpenInputDesktop` проверяются вручную: это вызовы Windows.
Миграции не нужны: схема БД не менялась.

## Проверка ввода текста (без отправки)

На экране Automation есть блок «Проверка ввода текста»: программа записывает пробный текст в поле ввода открытого чата
через шаблон Value, читает его обратно, сохраняет список кнопок окна (чтобы увидеть кнопку «Отправить») и очищает поле.
Ничего не отправляется. Чужой черновик в поле не трогается, при двух подходящих полях программа останавливается.
Отчёт сохраняется в `%LocalAppData%\JustInTime\ui-dumps\probe-*.txt`.

## Что добавлено на этапе 8 (основа Messaging Engine)

Готов общий каркас отправки и адаптер WhatsApp Desktop.

- **Получатель WhatsApp**: номер только в международном формате с плюсом (`+77011234567`; пробелы и скобки допустимы).
  Номер без плюса (`8701...`) и имя контакта отклоняются: код страны или контакт нельзя угадывать.
- **MessageSendExecutor**: проверяет получателя и текст, наличие подключения к сети (нет сети: задача ждёт, статус
  WaitingForNetwork), выбирает адаптер и переводит его результат в итог задачи:
  Sent → «Выполнено» (в сообщении указано, что доставка не проверяется), NotSent → «Ошибка» (повтор безопасен),
  Uncertain или исключение адаптера → «Требуется действие» (автоматического повтора нет, чтобы не было дубля).
- **Контракт адаптера** (`IMessengerAdapter`): до нажатия отправки любой сбой это NotSent; если после нажатия результат
  проверить не удалось, это Uncertain; неоднозначного получателя адаптер обязан отвергать.
- Задача отправки требует разблокированного рабочего стола (см. этап 6).

### WhatsApp Desktop

- В назначенное время приложение открывает чат по номеру через протокол `whatsapp://`, проверяет, что в окне WhatsApp
  открыт чат с этим номером, вводит текст и нажимает кнопку «Отправить».
- Если поле уже содержит черновик, приложение его не изменяет и не отправляет сообщение.
- Если не удаётся однозначно определить чат, поле ввода или кнопку отправки, задача завершается без отправки.
- После нажатия кнопки отправки при невозможности проверить результат задача помечается как «Требуется действие»;
  автоматического повтора нет, чтобы избежать дубля.
- Требуются установленный и авторизованный WhatsApp Desktop, включённый компьютер, вошедший пользователь и
  разблокированный рабочий стол. Интерфейс WhatsApp может меняться; при несовпадении элементов отправка остановится.
- Успех означает, что WhatsApp очистил поле после нажатия отправки. Приложение не подтверждает доставку или прочтение.

Тесты проверяют обработку черновика, открытие чата и неоднозначный исход отправки. Миграции не нужны.

## Что пока не реализовано

- Раздел Scheduled Messages: открывается как страница-заготовка.
- Повторяющиеся задачи (этап 4б, нужна миграция).
- Адаптер Telegram, распознавание текста на фото, авиарежим и мобильный интернет (у Windows нет для них официального API).
